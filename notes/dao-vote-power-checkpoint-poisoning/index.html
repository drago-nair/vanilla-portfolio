DAO Vote Power — Checkpoint Poisoning via Self-Transfer Validation Flaw in Solidity

 28 Jun 2026 · 4 min read

This write-up covers the DAO Vote Power challenge from Code Review Lab. It exposes a critical logical flaw in a governance token contract where a missing self-transfer check enables artificial voting power inflation through checkpoint poisoning.

Executive Summary

The GovCore contract manages historical voting power snapshots using a checkpoint architecture. However, due to a failure to validate identical source and destination addresses (from == to) during standard token transfers, the system suffers an internal ledger state mismatch — enabling exponential checkpoint inflation while the actual balance remains static.

Vulnerability Class: Governance Logic Subversion / Checkpoint Poisoning / Parameter Validation Flaw

The Vulnerable Mechanism

The architectural failure resides in how state tracking changes are divided sequentially:

function _update(address from, address to, uint256 value, bool mint) internal {
    if (mint) {
        _totalSupply += value;
    } else {
        _balances[from] -= value;
        _writeCheckpoint(from, _balances[from]);
    }
    _balances[to] += value;
    _writeCheckpoint(to, _balances[to]);
}

The Deep Mechanics: Box vs. List Inflation

How can an attacker generate millions of voting credits if their actual balance never scales?

The answer lies in the fundamental difference between how two state mechanisms operate:

Wallet Balance (Overwriting a Box)

The _balances[account] mapping acts as a solitary slot. During a self-transfer, subtraction reduces it to 0, and immediate addition sets it back. This is a destructive overwrite — only the terminal state survives.

Checkpoint Registry (Appending a List)

The checkpoint tracking system functions as a dynamic array. When _writeCheckpoint triggers twice within a single transaction loop — once after subtraction, once after addition — it pushes two independent entries into the sequence. The array grows; the balance doesn't.

Result: Running this via a high-velocity script expands the historical snapshot log exponentially, providing vast governance weight while the primary wallet balance remains unchanged.

Remediation

The fix is a single guard clause — bypass checkpoint writes entirely when no true positional shift occurs:

function _update(address from, address to, uint256 value, bool mint) internal {
    // 🛡️ The Fix: Halt process early if context maps to a self-transfer
    if (from == to && !mint) {
        return;
    }
    // ... proceed with balance subtraction and checkpoint tracking ...
}
 Self-transfers must be no-ops. A token sent to yourself should never generate new checkpoint entries. One if statement prevents infinite governance inflation.
