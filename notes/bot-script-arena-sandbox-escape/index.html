Bot Script Arena — Insecure Sandbox Isolation and Object Reference Injection in Otto VM

 28 Jun 2026 · 4 min read

This write-up covers the Bot Script Arena challenge from Code Review Lab. It exposes a critical backend sandbox evasion flaw — where a Go-based Otto JavaScript VM leaks live memory pointers into guest script contexts, enabling arbitrary state manipulation.

Executive Summary

The target architecture evaluates custom player scripts inside an Otto JavaScript VM context. However, structural boundary isolation collapses because the runtime framework introduces live pointer references of high-privilege server state objects directly into the guest runtime context via reflection. This breakdown facilitates arbitrary memory modification, global state contamination, and information disclosure across isolated instances.

Vulnerability Class: Insecure Sandbox Isolation / Privileged Memory Leak / Object Reference Injection

Vulnerability Analysis

The weakness manifests inside the Go-based backend script engine. The environment instantiates an isolated otto.New() execution boundary but subsequently invalidates its confinement parameters:

func (e *ScriptExecutor) RunBotScript(playerID string, script string) (*BotAction, error) {
    vm := otto.New()
    // Critical Flaw: Exporting live Go memory pointers into the guest context
    vm.Set("gameState", e.gameManager.GetGameState())
    vm.Set("playerData", e.gameManager.GetPlayerDataStore())
    vm.Set("moveUnit", func(call otto.FunctionCall) otto.Value {
        // ... function execution logic ...
        return otto.UndefinedValue()
    })
    _, err := vm.Run(script)
    // ... error handling ...
}

By mounting the active system pointers returned via GetGameState() and GetPlayerDataStore(), the engine builds an implicit, high-privilege bridge. The script runtime handles these instances not as isolated, pass-by-value configurations, but as directly linked channels to the host server's live memory addresses.

Exploitation Vector

Since Otto does not inherently enforce restrictive security sandboxing on raw components mounted through vm.Set(), any malicious script can bypass brokered game limits:

// 1. Mass Information Disclosure: Reading other connected player records
var allPlayers = playerData.getAllPlayers();

// 2. Integrity Contamination: Mutating live global server objects
gameState.setPlayerStats('attacker', {health: 999999, damage: 999999});

This injection completely breaks contextual multi-tenant match boundaries. Parameters injected by the script immediately register as absolute ground truth within the master server loop.

Remediation

  1. Enforce Pass-by-Value Data Snapshots: Never supply active pointers to live operational models. Serialize the explicit subset of permitted data into a deep-cloned structural copy or an isolated DTO.
  2. Decoupled Intermediary Brokers: Strip away accessors that bypass validation pipelines. Construct functional proxy callbacks that strictly validate authority metrics, parameter scope, and boundary conditions before enacting alterations.
